SECTION 1: PROBLEM STATEMENT
----------------------------------------------------------------
The current website was built in a 'vibe-coded' style — heavy
decorative effects, overly complex components, small animated
circles in the nav, inconsistent layout, and a footer that
still looks boxed and retro. The admin panel blended with the
background and was accessible from the nav (a security issue).
The result feels like an experiment, not a brand.

SOLUTION: Complete teardown of all UI components. Keep only:
  - app/ routing structure (Next.js App Router)
  - lib/ (auth, expoConfig, siteSettings)
  - data/ (seed data — content only)
  - API routes
  - tailwind.config.ts (tokens preserved, cleaned up)

================================================================

SECTION 2: DESIGN DIRECTION
================================================================
REFERENCE BRANDS: Google, Microsoft, Adidas, TCS, Linear, Stripe

COMMON PATTERNS ACROSS TOP BRAND WEBSITES:
  1. Whitespace is king — breathing room between sections
  2. One typeface family, two weights max per section
  3. One brand color, used sparingly (never decorative)
  4. Navigation: flat, text-only links. NO icons in nav
  5. Mobile-first grid: single column first
  6. Large, confident headlines (editorial)
  7. Dividers instead of cards with heavy borders
  8. Footer: simple, text-based, never 'boxed'
  9. CTAs: one primary (filled), one secondary (ghost)
 10. No gradients on text. No glowing borders on everything.

SECTION 5: PAGE STRUCTURE
----------------------------------------------------------------

HOME PAGE
  Hero        : Split — left text, right visual (stacked mobile)
  About Strip : 3 value props (icon + label + text, no card box)
  Events      : Upcoming events (from admin), each shows:
                  Event name, short desc, Free/Paid, Date & Time
  Team Preview: Grid of members with link to team page
  Footer      : Single-row text, no boxes

EVENTS PAGE (/events)
  Full list of events — admin managed

TEAM PAGE (/team)
  Photo grid — name, role, portfolio button (only if URL given)
  Portfolio button: ghost/outline style, appears conditionally

CONTACT PAGE (/contact)
  Email, socials, location. Minimal. Optional form.

ADMIN PAGE (/admin) — HIDDEN FROM NAV, PASSWORD PROTECTED
  Events Manager  : add / edit / delete events
  Team Manager    : add / edit / delete members, set roles
  Site Settings   : background toggle, other controls

SECTION 7: MOBILE-FIRST RULES
----------------------------------------------------------------
  1. Write all Tailwind classes mobile first, expand with md: lg:
  2. Touch targets: min 44x44px
  3. No font below 14px on mobile
  4. No horizontal scroll on any viewport
  5. Baseline test: 375px width (iPhone SE)
  6. Images: explicit width/height to prevent CLS

SECTION 9: PROS AND CONS
----------------------------------------------------------------
PROS:
  + Complete fresh start removes all vibe-code debt
  + Consistent design system — one token set, everywhere
  + Mobile-first: works on smallest screen first
  + Off-white + vermilion is a strong, distinctive palette
  + Syne + Plus Jakarta Sans is a proven editorial pairing
  + Admin is secure (not in nav, password gated)
  + Event cards admin-managed — no code changes needed
  + Portfolio button renders only when URL is present
  + Footer is text-based — no boxed appearance

CONS / RISKS:
  - Full rewrite = re-testing everything
  - Framer Motion transitions need careful SSR handling
  - Real E-Cell photograph needed for split hero
  - Admin data may need re-entry if DB is reset
